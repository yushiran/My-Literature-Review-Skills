# Getting the paywalled papers

The library a reviewer needs is not the open-access subset. In MR physics the
work sits in *Magnetic Resonance in Medicine* (Wiley), *NeuroImage* and *Medical
Image Analysis* (Elsevier), and IEEE *TMI* / *ISBI* / *TBME*; in most fields the
same is true of the journals that matter. `fetch.py` tries the open-access links
first and then, if they refuse, three further routes in this order.

| route | covers | credential | expires |
| --- | --- | --- | --- |
| Europe PMC | the deposited share of MRM, NeuroImage, TMI and most NIH-funded work | none | never |
| Wiley TDM API | MRM, NMR in Biomedicine, JMRI | a token | no |
| Elsevier API | NeuroImage, Medical Image Analysis, Magnetic Resonance Imaging | a key, plus an institutional token off campus | no |
| institutional EZproxy | Wiley, Springer, IEEE, SAGE, Taylor & Francis, IOP; **the only route for IEEE**, which has no mining API | a browser cookie jar | **hours** |

Verified against Bristol's proxy from a compute node, 2026-09-08: Wiley
(*Magnetic Resonance in Medicine*) and IEEE (*ISBI*) both return a real PDF;
Springer came down open-access without the proxy. **Elsevier does not work
through a proxy** and needs the API key: ScienceDirect resolves the DOI to a PII
happily enough, but its PDF link carries a one-time token generated by JavaScript
on the article page, so `/pdfft` and `/pdf` both return an interstitial. Do not
scrape around that. Either get the key or let those papers stay `no-pdf` with
their abstract in the index.

Publisher PDF paths are derived from the DOI prefix, because OpenAlex reports
`landing_page_url` as `https://doi.org/<doi>` rather than the publisher page.
IEEE is the interesting case: the article number that `stampPDF` needs is the
last dot-segment of the DOI, so `10.1109/isbi56570.2024.10635677` yields
`arnumber=10635677`. A direct publisher link that answered 403 is also retried
through the proxy, which is what rescues Wiley.

Nothing is on by default; with no configuration the behaviour is exactly as
before, plus Europe PMC. Put whatever is available in
`~/.config/litrev/access.env`, mode 0600:

```
LITREV_EZPROXY_HOST=bris.idm.oclc.org
LITREV_COOKIES=/home/<user>/.config/litrev/cookies.txt
WILEY_TDM_TOKEN=...
ELSEVIER_API_KEY=...
ELSEVIER_INSTTOKEN=...
```

`access.py` reads that file on import, so it survives across separate script
invocations, and refuses it if it is group- or world-readable. The agent must
never read the file, echo a token, or pass one on a command line.

## Getting the credentials

Walk the user through these in this order; the ranking is by value per minute of
their time, and each was tried for real.

**Wiley text-and-data-mining token — do this one first.** It covers *Magnetic
Resonance in Medicine*, which for an MRF or qMRI library is the single most
valuable journal, and unlike a cookie it does not expire. The user signs in to
Wiley Online Library with the institutional account and generates the token from
the account page; the entry point is
https://onlinelibrary.wiley.com/library-info/resources/text-and-datamining. If
that page asks them to contact the library instead, the institution has not
switched TDM rights on yet and one email saying "text and data mining token for a
non-commercial research literature review" is normally enough. The token is a
UUID. Verified 2026-09-08: with it, paywalled MRM articles download directly,
2--6 MB each, via the `wiley-tdm` route and no proxy.

**Elsevier — the key is instant and, off campus, not sufficient on its own.**
Register at https://dev.elsevier.com/, "My API Key" then "Create API Key", which
takes two minutes and asks only for a label. That gets metadata and open-access
full text. Subscribed full text additionally needs *entitlement*, which comes
either from the request originating inside the institution's IP range or from an
**institutional token** that Elsevier support issues through the library.
Verified 2026-09-08 from an off-campus compute node: the key alone returns 403 on
*NeuroImage* and *Medical Image Analysis*, and the proxy cannot substitute,
because the ScienceDirect PDF link carries a JavaScript-generated one-time token.
So for Elsevier the sequence is: get the key now, then ask the library to request
an `insttoken` for the API. Until it arrives those papers stay `no-pdf` with their
abstract in the index, which is a perfectly usable state.

**IEEE — nothing to apply for.** No mining API exists, so *TMI*, *ISBI* and
*TBME* are reachable only through the proxy. This is why the cookie route is
permanent infrastructure rather than a stopgap.

**Europe PMC — nothing to apply for**, and it is already on.

Do not tell the user a paper is unavailable until the routes their credentials
actually enable have been tried. Before a batch, run one known-paywalled paper
per publisher and report which routes answered.

## Finding the proxy host

Ask the user to open any subscribed article from the library's own search page
and read the address bar. An OCLC-hosted EZproxy rewrites the host by turning
every dot into a dash and appending its own domain:

```
https://link.springer.com/article/10.1007/...
    becomes
https://link-springer-com.bris.idm.oclc.org/article/10.1007/...
                          ^^^^^^^^^^^^^^^^^ this is LITREV_EZPROXY_HOST
```

`access.py` builds exactly this form, which keeps the path, so a direct PDF link
stays a direct PDF link. The `login?url=` form does not, which is why it is not
used. If the address bar shows no proxy at all the user is on the campus network
and IP-authenticated; a cookie jar is then unnecessary but also harmless.

## Exporting the cookie jar

Tell the user, in this order:

1. Sign in: open a subscribed article through the library so the address bar
   shows the proxy host.
2. Install a cookie exporter, for instance the "Get cookies.txt LOCALLY"
   extension for Chrome or Firefox.
3. Export **on that proxied page**, and make sure the `.idm.oclc.org` cookies are
   included — EZproxy keeps the whole session in `ezproxy`, `ezproxyl` and
   `ezproxyn` on that domain, not in the publisher's own cookies. Exporting
   everything for the current site is the safe choice.
4. Put the file at `~/.config/litrev/cookies.txt` and `chmod 600` it. Do not
   paste the contents into the chat: those three values *are* the session.
5. Say so, and the agent verifies one paywalled PDF before starting a batch.

A one-paper verification is worth the minute it costs. Without it a stale jar
looks identical to a paper that genuinely has no copy.

## The expiry problem, and what actually solves it

EZproxy sessions end on an idle timeout, typically two hours, and on an absolute
cap, often eight to twelve. Three things follow.

**A run that is actively downloading keeps its own session alive.** The idle
timer resets on every request, so fetching a hundred papers in one pass is
normally well inside the window. The danger is a long pause in the middle, or
resuming a library days later.

**A dead session used to be indistinguishable from a missing paper.** EZproxy
answers `200` with its login page, `fetch.py` correctly reads that as "not a
PDF", and every remaining paper would have been filed `no-pdf` with nobody the
wiser. It now recognises the bounce to `login.*.oclc.org`, raises
`SessionExpired`, leaves those papers `selected` rather than `no-pdf`, stops with
exit 2 and says to re-export. So the failure mode is now loud and fully
recoverable: re-export the jar, run `fetch.py --retry-no-pdf`, and only the
papers that are genuinely unavailable stay behind.

**For Wiley and Elsevier, the durable answer is a token, not a cookie.** Both
publishers issue one to subscribing institutions precisely so that content can be
fetched programmatically, and it does not expire. Wiley covers *Magnetic
Resonance in Medicine*, which for an MRF library is the single most valuable
journal, so if the user will obtain only one credential this is the one to ask
for:

- Wiley: https://onlinelibrary.wiley.com/library-info/resources/text-and-datamining
- Elsevier: https://dev.elsevier.com/ for the key; the institutional token comes
  from the library, and is needed whenever the request does not originate from a
  subscribing IP range.

IEEE has neither, so the proxy remains the only way to reach TMI, ISBI and TBME.
That is the part of the workflow that will always need a fresh cookie jar.

## Why the conversion step cares

MinerU is normally handed a URL so that its own servers fetch the paper and
nothing is uploaded from the local machine. That is wrong for a paper obtained
through the proxy or a mining API: MinerU holds none of our credentials, so it
would fetch a login or paywall page and convert it into markdown that looks like
a paper. `fetch.py` therefore records the route in `pdf_via`, and `convert.py`
uploads the local file instead whenever that route was `ezproxy`, `wiley-tdm` or
`elsevier-api`. Uploads are slower and time out on some campus networks; if they
do, `convert.py --retry-failed` retries only those.

## Scale

This is for reading a library the user is entitled to read, at the scale of one
review. `fetch.py` holds publisher and proxy hosts to a single concurrent request
with a 1.5 second pause, which is what mining terms ask for. Do not raise it, and
do not use these routes to mirror a journal.
